Private household records guide

Use fictional records to define what belongs to each person, what a household shares, and how recovery should be tested.

Example data only. Per-person permissions are planned.

Download printable guide (PDF)
In order
  1. Identify the smallest useful record
  2. Set explicit sharing rules
  3. Check the planned boundaries
  4. Price, maintain, and test recovery
  5. Upgrade with a rollback test

1. Identify the smallest useful record

Use examples such as a personal routine and a shared grocery list. Identify the subject, owner, purpose, audience, and how long it needs to be retained. Classify personal records as private by default. Identify who can approve changes. NIST privacy guide (PDF)

2. Set explicit sharing rules

Use two fictional people, A and B. A can read and update A’s personal record. B can read and update B’s record. Both can read the shared list. Set any write permission on the shared list explicitly. Test the proposed rules with read, edit, search, export, and sharing actions.

3. Check the planned boundaries

  1. Use a disposable sample environment. Load one record per person and one shared record.
  2. Check what each sees on direct and aggregate views. Record the expected versus observed result for each action.
  3. Revoke a sample share and confirm it disappears from the person’s view and subsequent exports.

In an example with eight correct results out of nine, the sample passes about 89% of checks. Investigate the failed access check and rerun the full sample before relying on personal separation. The current prototype uses shared household roles.

4. Price, maintain, and test recovery

Budget local storage, encrypted backup media, restore time, and whoever is responsible for review. An example 1 GB export kept in two locations uses about 2 GB before version history. Test restore in an isolated environment and confirm that the expected permissions and record counts survived.

5. Upgrade with a rollback test

Before updating the application or rules, keep a protected backup and run the sample checks. Re-run privacy and recovery after upgrading. A private record may leave its normal audience only under a specific documented decision covering the purpose and fields.
