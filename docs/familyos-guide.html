Private household records guide

Use fictional records to define what belongs to each person, what a household shares, and how recovery should be tested.

Example data only. Per-person permissions are planned.

In order
  1. Identify the smallest useful record
  2. Set explicit sharing rules
  3. Check the planned boundaries
  4. Price, maintain, and test recovery
  5. Upgrade with a rollback test

1. Identify the smallest useful record

Use fictional examples of a household task, an emergency check-in plan, a maintenance handoff, and a shared supply list. The design should account for household records during a routine week, an outage, and a long interruption. Identify the subject, owner, purpose, audience, and how long it needs to be retained. Classify personal records as private by default. Identify who can approve changes. NIST privacy guide (PDF)

2. Set explicit sharing rules

Use two fictional people, A and B. A can read and update A’s personal record. B can read and update B’s record. Both can read the shared list. Set any write permission on the shared list explicitly. Test the proposed rules with read, edit, search, export, and sharing actions.

3. Check the planned boundaries

  1. Use a disposable sample environment. Load one record per person and one shared record.
  2. Check what each sees on direct and aggregate views. Record the expected versus observed result for each action.
  3. Revoke a sample share and confirm it disappears from the person’s view and subsequent exports.

A failed access boundary blocks the release. Fix it and repeat the full sample. The current prototype uses shared household roles. Individual permissions are still planned.

Expected results in a fictional practice run
ScenarioExpected result
Person A opens A’s journalAllowed.
Person B tries A’s journal directly or in searchDenied directly. No matching item, snippet, or count revealed in search.
Person B opens the shared supply listAllowed to read while shared. Editing stays with A in this exercise.
Person B exports their dataIncludes B’s permitted records and excludes A’s journal. Check the file itself.
Share withdrawn, then backup restoredReapply newer sharing decisions before restoring household access. B still cannot open the withdrawn item.

4. Price, maintain, and test recovery

Budget local storage, encrypted backup media, restore time, and whoever is responsible for review. An example 1 GB export kept in two locations uses about 2 GB before version history. Test restore in an isolated environment and confirm that the expected permissions and record counts survived. Agree on who may hold an offline emergency copy and how to update or withdraw it.

5. Upgrade with a rollback test

Before updating the application or rules, keep a protected backup and run the sample checks. Re-run privacy and recovery after upgrading. A private record may leave its normal audience only under a specific documented decision covering the purpose and fields.
