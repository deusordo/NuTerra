In order
  1. Define the outcome
  2. Gather the inputs
  3. Price and plan the pilot
  4. Build and test
  5. Maintain and upgrade

1. Define the outcome

Start with a service that saves work or builds a skill in everyday life. Plan a fallback for an outage and a way to keep the service going through a long interruption. Name one result, one owner, one reviewer, and the person who will use it. Write the pass condition in plain language. For the offline handoff, a second person should be able to update an inventory using the saved guide with the internet disconnected.

2. Gather the inputs

SOURCE records the public evidence and rights. NuMind prepares the instructions. VIO packages the files and tests the restore. VATRA supplies the setting for the trial, and DEUS ORDO can organize volunteers when the work is appropriate. FamilyOS keeps household records private. Use the same service and handoff model for water, food, solar and backup power, communications, and routine repairs as each pillar builds out its guides. An evidence record for this pilot can use fictional inventory items.

See each pillar’s role · Download the handoff checklist

3. Price and plan the pilot

List prerequisites, storage, printing, materials, and staff or volunteer time. Keep cash and donated labor visible as separate figures. An example budget of $25 in supplies and 4 paid hours at $25/hour totals $125 before travel or reserves. Replace both inputs with actual figures.

4. Build and test

  1. Give the pilot an identifier and record the version, sources, and checksum.
  2. Restore it to a clean folder on a second device and disconnect the device.
  3. Ask a new reader to complete one task without coaching. Record what they finished, where they got stuck, and elapsed time.

One Community’s progress notes separate designs in progress from work performed. Use that distinction in our own log. One Community’s progress records

5. Maintain and upgrade

Assign someone to update links and files. Track recurring effort avoided and the time spent on upkeep. Teach the handoff so the work can be shared, with room for family time, learning, rest, and service. Save the previous release and a short change record. Rerun restoration and the user task after an update. A second-person handoff remains a separate test from opening files and verifying their hashes.
